### Q1 — `admin-dash/plans/page.js` + `_components/CurrentPlanCard.jsx` → **DELETE-FILE (whole route).**
Evidence chain (all verified): the page is a **client component** gated solely by `useAuthStore().isWhitelabel()` — it `router.replace("/admin-dash")` for every non-WL user (159-161) and runs its query `enabled: isWhitelabel()` (165). So after WL roles are gone there is **no audience and no server gate** — the route is dead. No non-WL backend counterpart exists (`manage-plans` is the admin plan-CRUD feature; `getWhitelabelPlans` is dead per backend inventory; the shared `availabilityEnum` only ties "whitelabel" to this self-checkout). **`_components/CurrentPlanCard.jsx` orphans** — its sole importer is this `page.js` (the host `CurrentPlanCard.js` is a *different* file under `host/plans/_components/`). `page.module.css` orphans too. Coupled cleanup: **C3** (navConfig `plans` rows) and **C1** (`useBusinessPlans`).

### Q2 — setup-password alignment with backend → **DELETE, confirmed whitelabel-only.**
Web evidence (file header, the lone `setupPassword`/`validateSetupToken` callers) + backend inventory (token minted only at `admin.whitelabels.service.updateWhitelabelStatus` + self-`resendSetupEmail`; hosts use `completeHostProfile`, moderators get an inline password) + shared inventory (paths labelled "Password Setup (Whitelabel)") agree. The shared `auth.validateSetupToken/setupPassword/resendSetupEmail` paths + backend routes are the backend agent's removal.

### Q3 — navConfig ↔ `@halla/shared` ordering → **HIGH; safe order = edit navConfig FIRST (or lockstep).**
`WHITELABEL_ROLES`/`isWhitelabelRole` are imported from `@halla/shared/constants/roles` **only** by `navConfig.js` (28-30), then re-exported by `navConfig.js:40` and `ui/layout/index.js:13-15`. **No surviving consumer reads them** from `@/ui/layout` or navConfig: DashboardStats/DashboardCharts define their **own local** `isWhitelabelRole`; serverAuth/middleware have their **own local** copies. So the only live use is `navConfig.js:551` (`getNavItemsForRole`'s `isWhitelabelRole(userRole)` vendors/whitelabels filter).
**Hazard:** if `shared` drops the exports *before* navConfig stops importing them, navConfig's **named import of `undefined` throws at module load** → `ui/layout/index.js` barrel throws → every layout that does `import { Header, ResponsiveSidebar, DASHBOARD_TYPES } from "@/ui/layout"` (admin-dash, host, vendor-dashboard layouts) crashes → **all dashboards down.**
**Prescription:** In navConfig, in one commit: drop the L28/30 import, the L40 re-export, the `ui/layout/index.js:13-15` re-exports, **and** delete the L551 `isWhitelabelRole` filter **together with** the `whitelabels` nav item + the WL `ROLE_NAV_ACCESS`/`ROLE_PAGE_ACCESS` rows + `DASHBOARD_TYPES.WHITELABEL` + `whitelabelNavItems` + the `getNavItems` WHITELABEL case + `getDashboardTypeFromPath`/`getBasePath` whitelabel branches + `PERMISSION_TO_NAV_KEY.manage_whitelabels` (518) + the `WHITELABEL_MODERATOR` branch in `canAccessPage` (574-593). Land this **before or in the same change as** the shared export removal. After these edits, super_admin/admin/moderator nav + page access are **byte-for-byte unchanged** (their rows are untouched; only the WL rows and the WL-only `isWhitelabelRole` filter — which only ever hid `vendors`/`whitelabels` from WL roles — are removed, and `whitelabels` itself is removed for everyone). Also de-whitelabel the **mirror** `notificationPreferencesSchemas.js` re-exports in lockstep with `@halla/shared/schemas/settings` (same named-import-crash hazard).
